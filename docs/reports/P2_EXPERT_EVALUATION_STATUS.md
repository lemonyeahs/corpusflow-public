# P2-Closure 专家评测准备状态

日期：2026-10-25。**专家评测系统已准备好用于受控小规模试标；真实专家参与 NOT RUN。** 角色名称、测试账号及自动化填写的分数不能证明专家资质或模型质量。

## 已实现

- 复用 User/Membership 的 reviewer/admin，新增 ReviewTask、ReviewAssignment，迁移 `0018_blind_review`。每任务 1–20 案例、2–5 位有效评测员；创建者与回答创建者不得自评。
- 固定 Trace、可选终态 GenerationRun、原文片段/来源/定位、查询、实际回答、rubric、分配名单及 SHA-256。数据库触发器禁止更新或删除任务与分配，复用不可覆盖的 RetrievalReview。
- 独立检查当前 RAG 与 evaluation 用途；仅有 RAG 授权不能推导评测授权。跨 workspace、他人分配、撤权证据均拒绝。
- 盲评接口与页面隐藏模型、检索策略、相似度、Trace/回答 ID 和他人评分；展示必要的原文、Segment 定位与待评回答。提交后只回显自己的分数，刷新不丢失。
- 一次提交全部案例、固定幂等键、不同内容重提冲突。普通评分入口不能使用盲评保留键，避免伪造分配评分或阻塞他人提交。
- 管理员导出 JSON：完整冻结范围、每人评分/理由/时间、分歧、精确一致率、平均绝对差及二次加权 κ。无有效分母/零期望方差时明确 NOT_EVALUATED。
- 创建、访问、评分及导出记录审计。计算使用任务冻结的维度，不随当前标准对象改变历史范围。

## 实际流程证据

`P2_CLOSURE_ANNOTATION_SAMPLE.json` 为实际 API + Web 导出的标注样例：2 个自制语料案例、2 位合成测试评测员、4 份不可改写的案例评分。复用既有成功回答和拒答，0 新模型调用。两位测试员故意填写 3 与 4，三个维度各有 2 个配对案例：精确一致率 0、平均绝对差 1、κ=0。这些值验证分歧计算，**不是实测专家一致性，也不是答案质量结论**。

`verify_closure_reviews.py` 实测分配隔离、跨空间拒绝、reviewer 导出拒绝、幂等、冲突提交、冻结快照 SQL 更新拒绝；Playwright 实际填写、提交、显示自己的分数、390px 操作、管理员导出并核对快照和统计。单元测试验证独立 evaluation 授权、授权撤销、伪造盲评键拒绝及 κ 边界；主机 PostgreSQL 迁移与不可变保护另有集成证据。

## 使用与 API

操作与标注标准见 `docs/demo/EXPERT_EVALUATION_GUIDE.md`。主要接口：

| 方法 | 路径（前缀 /api/v1） | 权限/用途 |
|---|---|---|
| POST | /review-tasks | admin；冻结任务、校验角色及用途 |
| GET | /review-tasks | admin；本空间任务摘要 |
| GET | /review-tasks/assignments | reviewer/admin；本人分配 |
| GET | /review-tasks/assignments/{id} | 本人；当前用途复检 |
| POST | /review-tasks/assignments/{id}/scores | 本人；不可变、幂等提交 |
| GET | /review-tasks/{id}/export | admin；当前用途复检与审计 |

参数和通用错误结构见 OpenAPI。新增表不替代已有评分历史，不更改任何已发布数据版本。

## 限制与正式评测前置条件

1. 专家资质、利益冲突、签字确认与真实独立评分尚未取得。当前身份仍为开发模式，不可用作生产身份认证。
2. 任务页面盲化不等于平台全局双盲；评测员可能从其他授权入口了解模型背景。正式项目需专用隔离空间和账号策略。
3. 没有“无法判断”逐例提交、任务撤回/重分配或内置仲裁流。不能判断时保留待评并由负责人新建明确案例；禁止用 0 代替缺失。
4. 小样本上 κ 可能不稳定，且一致性不等于正确性。当前 2 案例仅用于流程断言。
5. 任务列表最多返回 200 条，尚无大规模分页管理；原文 JSON 导出只有授权管理员可获取，使用者须遵守许可。
6. 本轮未执行更大生成实验，既有最多 10 次/每次 512 输出 Token 预算不变。
