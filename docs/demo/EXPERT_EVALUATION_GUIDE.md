# 专家评测操作指南与标注标准

适用版本：`blind-evidence.v1`，数据库 `0018_blind_review`。系统已具备分配、独立评分和导出能力；当前测试身份不代表专家资格，没有完成真实专家评测。

## 负责人准备

1. 确认评测数据的 RAG 和 evaluation 用途均有有效依据。授权不相互推导；撤销后再次查看、评分或导出应拒绝。
2. 由业务负责人线下确认评测员专业领域、利益冲突、知情同意和身份。当前没有资质认证服务，也没有生产 OIDC，开发环境仅供受控演示。
3. 选取固定版本的实际检索 Trace；评价回答时同时选择与该 Trace 对应的终态回答 ID。无答案案例可用于测试合理拒答。不要为演示重复调用模型。
4. 在「盲评任务」填写 Trace ID、可选的回答 ID、2–5 位评测员的内部 User ID。每行一项、顺序对应，最多 20 案例。任务创建者及回答创建者不能作为相应评测员。
5. 点击「冻结并分配」，记录任务 ID 和快照 SHA-256。证据文本、来源定位、查询、回答、标准和分配名单被固定。修改数据、规则、名单或纠错必须新建任务，不能覆盖旧快照。
6. 正式使用前进行少量独立试标。由负责人检查误解与无法判断案例，修订标准并重新冻结；不要把试标分数混入正式效果结论。

## 评测员操作

以自己的身份选择工作空间，进入「盲评任务」→「我的任务」。只打开分配给自己的任务。核对任务快照、案例问题、待评回答及原文证据。展开来源定位，必要时联系负责人提供可授权查看的完整上下文。

界面不展示模型名称、策略、相似度和其他人的评分，但同一平台其他授权入口可能泄漏背景；正式严格盲评应使用专用工作空间/受限账号及组织流程。本版本不能宣称平台范围的完全双盲。

按三个维度分别评分，不从相似度推导正确性：

| 分数 | 证据支持 evidence_support | 完整性 completeness | 答案正确性 answer_correctness |
|---|---|---|---|
| 0 | 无相关证据或与结论冲突 | 关键问题未覆盖 | 核心结论错误 |
| 1 | 仅少量证据相关 | 大部分关键点缺失 | 大部分关键结论错误 |
| 2 | 部分结论有证据 | 约半数必要要点覆盖 | 正误混合，存在实质问题 |
| 3 | 关键结论有依据，小范围不足 | 主要要点齐全，有小遗漏 | 基本正确，有小错误 |
| 4 | 所有关键结论可定位到充分证据 | 在问题要求范围内完整 | 核心及细节正确，无实质错误 |

检索专用案例没有答案正确性分数。对无答案案例，充分且正确的拒答可以有高答案正确性分数；检索证据不足应如实单独评分。勾选「应拒答」「证据不相关」「回答无依据」时，在理由中说明判据。每例必须填写至少 8 字符的理由，推荐「结论—证据编号/原文位置—缺陷或支持理由」。避免粘贴无权分发的正文。

无法可靠判断、材料缺失或公式无法读取时，**不要猜分或填 0 充当缺失值**。联系负责人重建清晰案例。本版本没有逐案例“无法判断”提交/仲裁流，该任务应保持待评；这是正式大规模标注前需完善的限制。

独立完成所有案例后提交。提交不可改写；刷新后能查看自己的分数，不能查看同任务其他评测员的分数。不得交流分数后再伪装为独立评分。

## 汇总、分歧与导出

负责人输入任务 ID，查看汇总并下载 JSON。报告保存任务哈希、完整输入快照、每人评分和理由、时间、成对一致性。仅完整提交的两位评测员对共同案例参与比较：

- 精确一致率 = 同分案例数 / 配对案例数。
- 平均绝对差 = 各案例分差绝对值之和 / 配对案例数。
- 二次加权 κ = 1 − 观测均方差 / 边际分布独立配对期望均方差；期望为 0 时输出 NOT_EVALUATED，不填 1。

这些统计衡量标注一致性，不证明答案准确性或专家资格。小样本不能外推总体效果。出现显著分歧时保留原始评分，负责人线下组织仲裁并建立新任务/单独附录，记录原任务 ID。当前没有自动仲裁、专家资质库或大任务分页管理。

正式交付应同时提供签字/资质依据、数据许可、冻结任务、原始评分、分歧处理记录及抽样方法；在这些材料齐备前只声明“专家评测系统已准备好”。
